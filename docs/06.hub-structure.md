## 1. 한 줄 정의

**허브 구조**란 중앙 분기점에서 여러 갈래 중 하나를 골라 갔다가, 끝나면 **다시 중앙으로 돌아오는** 반복 구조다.
**허브 이벤트**는 그 갈래 하나하나를 가리킨다.

이 프로젝트에서 중앙에 해당하는 레이블이 `AprilHub`이고, 허브 이벤트는 4월의 학교 일상 6종이다.

---

## 2. 전체 그림

```
프롤로그~3화(선형 도입부)를 지난 뒤 허브가 시작된다.

```
  프롤로그 → 1화 → 2화 → 3화
        (선형 도입부)
              │
              ↓
        ┌──────────────────┐
   ┌───→│     AprilHub     │  "나는 오늘, 수아를…"
   │    └────────┬─────────┘
   │             │  4개 중 하나 선택 (이미 본 것은 숨김)
   │      ┌──────┼──────┬──────┐
   │      ↓      ↓      ↓      ↓
   │     조별   점심   수학   보지
   │     수업   시간   여행  않았다
   │      │      │      │      │
   │      └──────┼──────┴──────┘
   │             │  거리감 변동 + april_events +1 + distance +10
   │             ↓
   │        [조건 분기]
   │             │
   │   ┌─────────┼──────────────┐
   │   ↓         ↓              ↓
   │ distance   april_events   그 외
   │  >= 80      >= 3
   │   ↓         ↓              │
   │ GameOver  CrackIntro       │
   │           (균열 파트)       │
   └───────────────────────────┘
              반복
```

**최소 3회 반복**하고 거리감이 80 미만이면 5월 균열 파트로 넘어간다. 4개를 다 볼 필요는 없다.

---

## 3. 플레이어가 보는 것

허브에 진입할 때마다 이런 선택 화면이 뜬다.

```
                나는 오늘, 수아를…

           ┌────────────────────────────┐
           │  조별 수업 시간에 보았다      │
           ├────────────────────────────┤
           │  점심시간에 보았다           │
           ├────────────────────────────┤
           │  수학여행에서 보았다         │
           ├────────────────────────────┤
           │  보지 않았다                │
           └────────────────────────────┘
```

한 번 본 이벤트는 **다음 진입부터 목록에서 사라진다**(H-1 확정). 3회를 채우면 균열 파트로 넘어가므로, 4개 중 **하나는 반드시 보지 않게 된다.**

하나를 고르면 그 이벤트가 재생되고, 이벤트 **안에서 다시** 선택지가 나와 거리감이 오르내린다. 끝나면 이 화면으로 돌아온다.

정해진 순서가 없다는 것이 핵심이다. 플레이어가 고르는 대로 4월이 전개되고, **회차마다 다른 조합**을 볼 수 있다.

---

## 4. 허브 이벤트 한 개의 해부

모든 허브 이벤트는 **2단계 선택지**로 구성된다.

| 단계 | 역할 | 거리감 |
|------|------|--------|
| **1차 선택지** | 수아에게 어떻게 반응할지 | **변동 있음** (±15 / ±5) |
| **2차 선택지** | 대화를 어떻게 이어갈지 | 변동 없음 (플레이어 취향) |

### 조별수업 이벤트 예

```
GroupProject (진입)
   │
   ├─ 1차 ─┬─ 나서서 정해준다      distance -5   ← 최선
   │       └─ 역할을 묻는다        distance +5   ← 악수(惡手)
   │
   └─ 2차 ─┬─ 발표 경험 물어보기   변동 없음
           └─ PPT 질문하기        변동 없음
   │
   └─→ GroupProject_End → april_events +1, distance +10 → [조건 분기] → AprilHub
```

### 거리감 설계 의도

`03.game-design.md` 3.1에 근거가 있다.

- **"보지 않았다"가 마이너스(가까워짐)** 인 이유 — 억지로 다가가지 않는 것이 수아에게 부담을 주지 않기 때문이다. 아무것도 안 하는 선택이 최선일 수 있다는 것이 이 게임의 주제다.
  → 단, 2026-08-02 확정으로 값이 **−15에서 −5로 낮아졌다**(H-2). 여전히 유효한 선택이지만 최선은 아니다.
- **"역할을 묻는다"·"힐끗 봤다"가 플러스(멀어짐)** 인 이유 — 수아에게 판단을 떠넘기거나 관찰에 그치는 행동은, 수아가 "현우는 나와 다른 세계 사람"이라고 느끼게 만들기 때문이다.

## 5. 반대 구조 — 선형

균열 파트(5~6월)는 허브가 아니다.

```
CrackIntro → 방과후 → 급식시간 → 체육대회 → 기말고사 → 생일 → JulyIntro
```

순서가 고정이고 건너뛸 수 없다. 각 이벤트 안에 선택지는 있지만 **어느 이벤트를 할지는 고를 수 없다.**

| | 허브 (4월) | 선형 (5~6월) |
|---|---|---|
| 순서 | 플레이어가 결정 | 고정 |
| 반복 | 있음 (최소 3회) | 없음 |
| 진행 조건 | `april_events >= 3` | 이벤트 완료 시 다음으로 |
| 실패 조건 | `distance >= 80` | 선택지 오답 |
| 서사 성격 | 관계의 **누적** | 갈등의 **전개** |

이 대비 자체가 기획 의도다. 4월은 쌓아 올리는 시기, 5~6월은 무너지고 회복하는 시기다.

## 6. 무엇이 허브 이벤트가 될 수 있는가

새 원고([01.new_story.md](01.new_story.md))를 배치할 때 판정 기준이 된다. **세 조건을 모두 만족해야** 허브 이벤트가 될 수 있다.

| 조건 | 이유 | 위반하면 |
|------|------|---------|
| **① 순서에 의존하지 않는다** | 허브는 선택 순서를 보장하지 않는다 | 앞 사건을 전제한 장면이 먼저 나와 말이 안 된다 |
| **② 세계 상태를 비가역적으로 바꾸지 않는다** | 최대 6회까지 반복 진입할 수 있다 | 되돌릴 수 없는 사건이 두 번 일어난다 |
| **③ 그 자체로 완결된다** | 끝나면 반드시 허브로 복귀한다 | 이야기가 중간에 끊긴 채 선택 화면이 뜬다 |

### 새 원고 적용 결과

| 원고 | ① 순서 무관 | ② 가역적 | ③ 완결 | 판정 |
|------|:---:|:---:|:---:|------|
| 프롤로그 | ❌ | — | — | 도입부. 항상 첫 번째 |
| 1화 (첫 합석) | ❌ | ❌ | ✅ | **불가** — "처음 말을 건다"는 한 번뿐 |
| 2화 (자리 바꾸기) | ❌ | ❌ | ✅ | **불가** — 자리는 두 번 바꿀 수 없다 |
| 3화 (수학 시간) | ❌ | ✅ | ✅ | **불가** — "옆자리"(2화 결과)가 전제 |

**→ 프롤로그~3화는 전부 선형 도입부다.** 기존 기획이 자리배정·수학시간을 허브 이벤트로 잡아둔 것과 충돌하며, 이것이 [05.continuity.md](05.continuity.md)의 **C-5·C-6**이다.

### 확정 구조 (2026-08-02)

```
프롤로그 → 1화 → 2화 → 3화 ─→ AprilHub ─┬→ 조별수업
        (선형 도입부)                    ├→ 점심시간
                                        ├→ 수학여행
                                        ├→ 보지 않았다
                                        └→ (추가 이벤트)
                                              ↓
                                         균열 파트
```

자리배정과 수학시간을 허브 목록에서 빼고 도입부로 옮긴다. 허브는 **4화부터** 시작한다.
이러면 기존 허브 메커니즘을 그대로 유지하면서 원고의 선형성도 지킬 수 있다. 다만 허브 이벤트가 4종으로 줄어드는 문제는 아래 H-6에서 다룬다.

## 7. 구조적 허점 — 진단

허점은 하나가 아니라 **셋이 연쇄되어 있다.** 앞의 것을 고치면 뒤의 것이 드러난다.

```
H-1  이벤트 중복 선택 가능
       ↓ 고치면 드러남
H-2  게임오버가 수학적으로 불가능
       ↓ 고치면 드러남
H-3  4월의 선택이 결과에 아무 영향이 없음
```

지금은 H-1이 H-2를 가려주고 있다. **현재 게임오버에 도달하는 유일한 경로가 H-1(같은 이벤트 반복)** 이므로, 실패 조건이 버그에 의존하는 상태다.

### H-1. 같은 이벤트를 반복해도 진행된다

`april_events >= 4`만 검사하므로 자리배정을 4번 골라도 균열 파트로 넘어간다. 같은 장면을 네 번 보게 된다.
→ 구현 해법은 [07.hub-implementation.md](07.hub-implementation.md) 5절.

### H-2. 게임오버에 도달할 수 없다

> 아래는 **확정 전(허브 이벤트 6종·페널티 없음) 기준의 진단**이다. 확정 후 수치는 8-1절 검산표를 따른다.

거리감을 **올리는** 선택지는 게임 전체에 세 개뿐이다.

| 이벤트 | 선택지 | 변화 |
|---|---|---|
| 자리배정 | 친구와 대화한다 | **+15** |
| 조별수업 | 역할을 묻는다 | **+5** |
| 수학여행 | 힐끗 봤다 | **+5** |
| | **합계** | **+25** |

나머지 세 이벤트(수학시간·보지않았다·점심시간)는 **어느 선택지를 골라도 거리감이 줄어든다.**

```
초기값                    50
+ 친구와 대화한다         +15  → 65
+ 역할을 묻는다            +5  → 70
+ 힐끗 봤다                +5  → 75
+ 4회차는 음수뿐          -5  → 70   ← 4회를 채우려면 반드시 손해
                              ────
최대 도달치                    70   <  게임오버 80
```

**의도적으로 최악만 골라도 70이다.**

### H-3. 4월에 무엇을 골라도 결말이 같다

엔딩은 `JulyChoice`의 3택으로만 갈린다. **거리감은 엔딩 분기에 전혀 참여하지 않는다.**
게임오버만 피하면 4월 플레이는 결과에 무영향이고, H-2에 따라 게임오버는 불가능하다. 결국 **4월 파트 전체가 최종 결과와 무관**하며, 플레이어가 최적화할 것이 없다.

## 8. 밸런스 보완안

### H-2 → 시간 경과 페널티 **+10** (확정)

허브로 복귀할 때마다 `distance +10`을 적용한다.

서사적으로도 맞는다. **가만히 있으면 자연히 멀어진다** — 수아는 먼저 다가오지 않는 캐릭터이고, 프롤로그가 통째로 그것을 보여준다. 플레이어의 행위가 "관계를 쌓는 것"에서 **"흘러가는 시간을 거스르는 것"** 으로 바뀐다.

> **부수 조정**: 이대로면 "보지 않았다"(−15)가 페널티를 상쇄하고도 남아 **아무것도 안 하는 것이 최선**이 된다. 이 값을 **−5로 낮춰** 유효하되 최선은 아니게 조정한다. 기획 의도("부담을 주지 않아 가까워진다")는 유지된다.

#### 왜 +5가 아니라 +10인가

C-5·C-6 확정(자리배정·수학시간을 도입부로 이관)으로 **유일한 +15 선택지("친구와 대화한다")가 허브에서 빠져나갔다.** 남은 허브 4종의 양수 선택지는 조별수업 +5, 수학여행 +5 뿐이다.

```
페널티 +5일 때  최악 = 50 + 10(양수) − 5 + 15(경과 3회) = 70  < 80  ❌ 도달 불가
페널티 +10일 때 최악 = 50 + 10(양수) − 5 + 30(경과 3회) = 85  ≥ 80  ✅
```

**대안 비교**

| 안 | 방법 | 평가 |
|---|---|---|
| 임계값 인하 | 80 → 65 | 가장 싸지만 아슬아슬 |
| 양수 선택지 증설 | 이벤트마다 +선택지 보장 | 원고 재작성 필요. 비용 큼 |
| **시간 경과 페널티 +10** | 허브 복귀마다 | **확정.** 수치 한 줄, 서사와 정합 |

### H-3 → 엔딩 조건에 거리감 참여 (확정, 임계값 **45**)

*"말 없이 멀어지지 않을게"*(엔딩 A 선택지)를 골라도 **관계가 충분히 쌓이지 않았으면 엔딩 B로 보낸다.**

| 최종 선택 | 추가 조건 | 도달 엔딩 |
|---|---|---|
| A "말 없이 멀어지지 않을게" | `distance <= 45` | 엔딩 A |
| A (조건 미달) | — | 엔딩 B |
| B "절대 그럴 일 없어" | — | 엔딩 B |
| C "다 이해해" | — | 엔딩 C |

> **임계값이 30이 아니라 45인 이유**: 페널티 +10 확정에 따라 **최선 플레이의 도달치가 45**가 되었다(아래 검산표). 30으로 두면 엔딩 A가 수학적으로 불가능해진다.

이건 밸런스 장치가 아니라 **주제의 구현**이다. 같은 말이라도 쌓아온 시간에 따라 다르게 닿는다 — 이 작품이 하려는 이야기 그 자체다. 그리고 4월의 모든 선택에 소급해서 의미가 생긴다.

### H-5 → 상태 피드백

`affinity_hint`는 선택 직후 1.4초만 표시된다. 4회 반복하는데 **누적 상태를 알 수 없어** 전략을 세울 수 없다.

허브 진입 시 현재 거리감을 내레이션으로 알린다.

| 거리감 | 문구 예 |
|---|---|
| ~50 | *"(요즘은 수아와 말이 잘 통하는 것 같다.)"* |
| 51~69 | *"(수아는 여전히 조용하다.)"* |
| 70~ | *"(요즘 수아가 나를 피하는 것 같다.)"* |

> 구간 기준은 8-1절의 확정 밸런스 분포(최선 45 ~ 최악 85)에 맞춘 것이다. 70 이상은 **게임 오버(80) 경고** 역할을 겸한다.

수치를 직접 노출하지 않는 것이 중요하다. 이 게임의 주제가 **"타인의 마음은 수치로 보이지 않는다"** 이기 때문이다.

### H-6 → 진행 조건 **3회** (확정)

6절의 구조 확정으로 허브 이벤트가 **4종**으로 줄어든다. `april_events >= 4`면 **전부 강제**가 되어 허브인 의미가 사라진다.

| 안 | 내용 | 평가 |
|---|---|---|
| **진행 조건 3회** | `april_events >= 3` | **확정.** 4종 중 3종 선택 → 자유도 확보 |
| 이벤트 2종 신설 | 원고 4~5화를 허브 이벤트로 집필 | 후속. 원고 필요 |

**단기는 3회로 낮추고, 원고 4~6화 집필 시 이벤트를 보강**하는 2단계 접근으로 확정한다.

## 8-1. 확정 밸런스 검산

### 확정 수치

| 항목 | 값 |
|------|-----|
| 초기 거리감 | 50 |
| 게임 오버 | `distance >= 80` |
| 진행 조건 | `april_events >= 3 AND distance < 80` |
| **시간 경과 페널티** | **허브 복귀마다 +10** |
| **엔딩 A 조건** | **`distance <= 45`** |

### 허브 이벤트 4종의 1차 선택지

| 이벤트 | 선택지 A | 선택지 B |
|---|---|---|
| 조별수업 | 나서서 정해준다 **−5** | 역할을 묻는다 **+5** |
| 점심시간 | 같이 먹자 **−15** | 음료수 사줌 **−5** |
| 수학여행 | 같이 다녔다 **−15** | 힐끗 봤다 **+5** |
| 보지 않았다 | (단일) **−5** | — |

### 3회 플레이 시나리오

| 플레이 | 선택 | 이벤트 합 | 경과 | 최종 | 결과 |
|---|---|---|---|---|---|
| **최선** | 점심 −15, 수학여행 −15, 조별 −5 | −35 | +30 | **45** | 엔딩 A 가능 ✅ |
| 차선 | 점심 −15, 수학여행 −15, 조별 +5 | −25 | +30 | **55** | 엔딩 B |
| 보통 | 점심 −5, 수학여행 −15, 보지않음 −5 | −25 | +30 | **55** | 엔딩 B |
| 악수 1회 | 조별 +5, 점심 −15, 수학여행 −15 | −25 | +30 | **55** | 엔딩 B |
| **최악** | 조별 +5, 수학여행 +5, 점심 −5 | +5 | +30 | **85** | 게임 오버 ✅ |

**설계 의도**

- **엔딩 A는 완벽한 4월을 보낸 플레이어에게만 열린다.** 최선 플레이의 도달치가 정확히 45이므로 한 번의 차선 선택도 허용되지 않는다. 진엔딩 성격을 부여한 것이다.
- **게임 오버는 악수를 2회 이상 둬야 발생한다.** 한 번의 실수(75)로는 실패하지 않는다.
- 대부분의 플레이는 엔딩 B로 수렴한다. 이는 의도된 결과다 — 엔딩 B가 이 작품의 기본값이며, A와 C가 양극단이다.

> ⚠️ **여유가 없는 밸런스다.** 엔딩 A의 마진이 0이므로, H-4(화제 플래그)나 이벤트 신설이 들어오면 재산출이 필요하다. 재산출 시 이 표를 갱신할 것.

---

## 9. 서사 보완안 — H-4 화제 플래그

2차 선택지는 거리감 변동이 없어 **결과에 아무 영향이 없다.** 플레이어에게 "선택했다"는 감각이 생기지 않는다.

거리감 대신 **화제 플래그**를 세우게 한다.

| 2차 선택지 | 세우는 플래그 | 균열 파트에서 |
|---|---|---|
| 게임 좋아해? | `topic_game` | 게임 이야기로 말을 걸 수 있다 |
| 과자 먹을래? | `topic_snack` | 간식을 나누는 선택지가 열린다 |
| 도시락 질문 | `topic_lunchbox` | 도시락 화제로 대화가 이어진다 |

4월에 알아낸 수아의 정보가 **균열 파트의 대화 카드**가 된다. 그러면 4월이 "점수 쌓기"가 아니라 **"사람을 알아가는 과정"** 이 된다.

원고가 이미 그렇게 쓰여 있다는 점이 중요하다. 2화에서 현우는 수아의 소설(《달빛 아래 우산》)과 게임 취향을 알아내고, 3화에서 도시락과 과목 취향을 알아낸다. **획득한 정보를 나중에 쓰는 구조**가 원고의 자연스러운 귀결이다.

> 비용이 가장 크다(균열 파트 원고에 분기 필요). 우선순위는 마지막이지만 **서사적 이득은 가장 크다.**
