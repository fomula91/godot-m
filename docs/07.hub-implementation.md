# 07. 허브 구조 — 기술 구현

> **상태**: 🟢 최신 (2026-08-02 신규, `06`에서 기술 파트 분리)
> **관점**: 이 문서는 **JSON을 어떻게 쓰는가 / 엔진이 어떻게 동작하는가**를 다룬다.
> **설계 의도·밸런스**는 → [06.hub-structure.md](06.hub-structure.md)
> **근거 코드**: `scripts/autoload/story_manager.gd`, `scripts/autoload/game_manager.gd`, `scenes/controller/choice_controller.gd`
> **구현 상태**: ❌ 아래 JSON은 전부 **설계 예시**이며 `story/`에 존재하지 않는다.

---

## 1. 레이블 구성

허브 하나는 최소 세 종류의 레이블로 이뤄진다.

| 종류 | 예 | 역할 |
|------|----|----|
| 허브 본체 | `AprilHub` | 선택 화면 표시 |
| 이벤트 본편 | `SeatAssignment`, `SeatAssignment_Hobby`, `SeatAssignment_2nd` … | 실제 내용 |
| 이벤트 종료 | `SeatAssignment_End` | 카운터 증가 + 조건 분기 + 허브 복귀 |

**종료 노드가 허브 구조의 심장이다.** 여기서 복귀가 누락되면 반복이 성립하지 않는다.

---

## 2. 허브 본체

```json
"AprilHub": [
  { "cmd": "show_scene", "id": "classroom_day", "transition": "fadeIn" },
  { "cmd": "narration", "text": "(오늘도 점심시간이 왔다.)" },
  { "cmd": "choice",
    "dialog": "나는 오늘, 수아를…",
    "choices": [
      { "text": "조별 수업 시간에 보았다", "key": "group", "target": "GroupProject" },
      { "text": "점심시간에 보았다",      "key": "lunch", "target": "LunchTime" },
      { "text": "수학여행에서 보았다",    "key": "trip",  "target": "SchoolTrip" },
      { "text": "보지 않았다",           "key": "none",  "target": "DidNotLook" }
    ]
  }
]
```

> `dialog`의 **첫 단어가 캐릭터 ID이면** 대사 형태로 표시된다(`choice_controller.gd:30`). 예: `"dialog": "sua 뭐 먹을래?"`. 위처럼 내레이션형 질문을 쓸 때는 첫 단어가 ID와 겹치지 않도록 주의한다.

## 3. 거리감 적용

1차 선택지 직후에 넣는다.

```json
"LunchTime_Together": [
  { "cmd": "set_var", "path": "distance", "value": 15, "op": "sub" },
  { "cmd": "affinity_hint", "character": "closer" },
  { "cmd": "dialogue", "character": "p", "text": "같이 먹을래?" }
]
```

| 필드 | 값 |
|---|---|
| `op` | `"set"` / `"add"` / `"sub"` |
| `affinity_hint.character` | `"closer"`(♡) 또는 `"farther"`(…) |

> ⚠️ `affinity_hint`의 필드명은 `character`지만 값은 **캐릭터 ID가 아니다.** 이름이 오해를 부르니 주의.

## 4. 이벤트 종료 — 허브 복귀

```json
"GroupProject_End": [
  { "cmd": "set_var", "path": "april_events", "value": 1,  "op": "add" },
  { "cmd": "set_var", "path": "distance",     "value": 10, "op": "add" },
  { "cmd": "conditional",
    "branches": [
      { "condition": "distance >= 80",    "action": "jump", "target": "GameOver" },
      { "condition": "april_events >= 3", "action": "jump", "target": "CrackIntro" }
    ],
    "default": "AprilHub"
  }
]
```

`branches`는 **위에서부터 순서대로** 평가되고 처음 참인 것에서 멈춘다. 게임오버 판정을 먼저 두어야 "거리감 80 이상인데 3회를 채웠다"는 상황에서 균열 파트로 새지 않는다.

> `distance +10`은 **시간 경과 페널티**(H-2)이고 `april_events >= 3`은 **진행 조건 인하**(H-6)다. 둘 다 2026-08-02 확정 사항이며 근거는 [06](06.hub-structure.md) 8-1절 검산표에 있다. **모든 이벤트 종료 노드가 이 형태를 따라야 한다.**

## 5. 엔진 제약 — 반드시 알아야 할 것

코드를 읽고 확인한 사항이다. 대부분 **에러 없이 조용히 잘못 동작**하므로 미리 알아야 한다.

| # | 제약 | 근거 | 증상 |
|---|------|------|------|
| 1 | **`"action": "jump"`가 없으면 진행이 멈춘다** | `story_manager.gd:356` — `action`이 `"jump"`가 아니면 점프하지 않고 그대로 `return` | 조건이 참인데 화면이 정지. **가장 잡기 어려운 버그** |
| 2 | **조건식에 괄호를 쓸 수 없다** | `game_manager.gd:91~108` — 문자열 split 방식 | `(a OR b) AND c` 불가 |
| 3 | **AND가 OR보다 먼저 쪼개진다** | 같은 곳 — `" AND "` 검사가 앞에 있음 | `a AND b OR c`가 `a AND (b OR c)`로 해석. 복합 조건은 분리할 것 |
| 4 | **정의되지 않은 변수는 0으로 취급된다** | `game_manager.gd:119` — `left == null`이면 `0` | `distnace` 같은 오타가 조용히 항상 거짓. 에러가 안 난다 |
| 5 | **선택지는 조건부로 숨길 수 없다** | `choice_controller.gd:45` — `for choice in choices`로 전부 버튼 생성 | H-1의 직접 원인. 6절에서 해결 |
| 6 | **통계 추적 대상이 코드에 하드코딩** | `story_manager.gd:86` `tracked_scenes` | 새 이벤트 레이블 추가 시 여기도 고쳐야 통계가 붙는다 |
| 7 | **`default` 없이 모든 조건이 거짓이면 다음 줄로 진행** | `story_manager.gd:364` | 허브 복귀가 누락되면 이벤트 뒤 엉뚱한 줄이 재생된다. **`default`는 반드시 명시** |
| 8 | **스토리 로드 디렉터리가 고정** | `story_manager.gd:114` — `["april","may","crack","july"]` | 다른 디렉터리에 둔 JSON은 **조용히 로드되지 않는다** |

## 6. H-1 구현 — 이벤트 중복 방지

[06](06.hub-structure.md) 7절의 H-1을 해소한다. 제약 5 때문에 JSON만으로는 불가능하며 **코드 3줄**이 필요하다.

### 6.1 엔진 확장

`choice_controller.gd`의 버튼 생성 루프에 조건 검사를 넣는다.

```gdscript
for choice in choices:
    var cond: String = choice.get("condition", "")
    if not cond.is_empty() and not GameManager.evaluate_condition(cond):
        continue                      # ← 추가되는 3줄
    var btn := Button.new()
    btn.text = choice.get("text", "")
    ...
```

`evaluate_condition`은 이미 존재하므로 재사용이다. `condition`이 없는 기존 선택지는 그대로 동작한다(하위 호환).

### 6.2 JSON 측

**허브 본체** — 각 선택지에 조건을 건다.

```json
{ "text": "조별 수업 시간에 보았다", "key": "group",
  "target": "GroupProject", "condition": "seen_group == 0" }
```

**이벤트 진입부** — 플래그를 세운다.

```json
"GroupProject": [
  { "cmd": "set_var", "path": "seen_group", "value": 1, "op": "set" },
  ...
]
```

제약 4에 따라 `seen_group`은 초기화하지 않아도 0으로 평가되므로 별도 초기화가 필요 없다.

**플래그 이름 규약** — `seen_{key}` 형태로 통일한다.

| 이벤트 | 플래그 |
|---|---|
| 조별수업 | `seen_group` |
| 점심시간 | `seen_lunch` |
| 수학여행 | `seen_trip` |
| 보지 않았다 | `seen_none` |

> **적용 범위**: 이 확장은 균열 파트와 엔딩 분기에서도 계속 쓰인다. **투자 대비 효과가 가장 크다.**

## 7. 보완안별 구현 명세

[06](06.hub-structure.md) 8~9절의 밸런스 결정을 JSON으로 옮기는 방법.

### H-2 — 시간 경과 페널티 (+10)

모든 이벤트 종료 노드에 한 줄 추가한다. 4절의 완성형 참조.

```json
{ "cmd": "set_var", "path": "distance", "value": 10, "op": "add" }
```

함께 `DidNotLook`의 거리감을 −15 → **−5**로 조정한다.

```json
"DidNotLook": [
  { "cmd": "set_var", "path": "seen_none", "value": 1, "op": "set" },
  { "cmd": "set_var", "path": "distance",  "value": 5, "op": "sub" },
  ...
]
```

### H-3 — 엔딩 조건에 거리감 참여 (임계값 45)

```json
"JulyChoice_A": [
  { "cmd": "conditional",
    "branches": [
      { "condition": "distance <= 45", "action": "jump", "target": "EndingA" }
    ],
    "default": "EndingB"
  }
]
```

### H-5 — 허브 상태 피드백

허브 본체 진입부에 넣는다. 조건 분기로 서로 다른 레이블에 보내고, 각 레이블 끝에서 선택 화면으로 모은다.

```json
"AprilHub": [
  { "cmd": "show_scene", "id": "classroom_day", "transition": "fadeIn" },
  { "cmd": "conditional",
    "branches": [
      { "condition": "distance <= 50", "action": "jump", "target": "AprilHub_Close" },
      { "condition": "distance >= 70", "action": "jump", "target": "AprilHub_Far" }
    ],
    "default": "AprilHub_Mid"
  }
],
"AprilHub_Close": [
  { "cmd": "narration", "text": "(요즘은 수아와 말이 잘 통하는 것 같다.)" },
  { "cmd": "jump", "target": "AprilHub_Menu" }
],
"AprilHub_Mid": [
  { "cmd": "narration", "text": "(수아는 여전히 조용하다.)" },
  { "cmd": "jump", "target": "AprilHub_Menu" }
],
"AprilHub_Far": [
  { "cmd": "narration", "text": "(요즘 수아가 나를 피하는 것 같다.)" },
  { "cmd": "jump", "target": "AprilHub_Menu" }
],
"AprilHub_Menu": [
  { "cmd": "choice", "dialog": "나는 오늘, 수아를…", "choices": [ ... ] }
]
```

> 제약 2(괄호 불가) 때문에 `31 <= distance AND distance <= 60` 같은 범위 조건은 쓸 수 없다. **`default`를 중간값으로 삼아** 위아래만 검사하는 것이 정석이다.

### H-6 — 진행 조건 인하

종료 노드의 조건식만 바꾼다.

```json
{ "condition": "april_events >= 3", "action": "jump", "target": "CrackIntro" }
```

### H-4 — 화제 플래그

2차 선택지에서 플래그를 세운다.

```json
"SeatAssignment_Game": [
  { "cmd": "set_var", "path": "topic_game", "value": 1, "op": "set" },
  ...
]
```

균열 파트에서 조건부 선택지로 사용한다(6.1의 엔진 확장 필요).

```json
{ "text": "게임 이야기를 꺼낸다", "key": "game",
  "target": "CrackLunchTime_Game", "condition": "topic_game == 1" }
```

## 8. 구현 체크리스트

허브를 실제로 만들 때 순서대로 확인한다.

- [ ] 이벤트 종료 노드마다 `april_events` 증가가 있는가
- [ ] 종료 노드의 `conditional`에 **`default`가 있는가** (제약 7)
- [ ] `branches`의 모든 항목에 **`"action": "jump"`가 있는가** (제약 1)
- [ ] 게임오버 판정이 진행 판정보다 **앞에** 있는가
- [ ] 조건식에 괄호가 없는가 (제약 2)
- [ ] 조건식의 변수명 오타가 없는가 — 오타는 에러 없이 항상 거짓 (제약 4)
- [ ] 새 이벤트 레이블을 `tracked_scenes`에 등록했는가 (제약 6)
- [ ] JSON이 `story/{april,may,crack,july}/` 아래에 있는가 (제약 8)
- [ ] 모든 `target`이 실존 레이블인가

## 9. 검증 방법

`CLAUDE.md`의 검증 규칙을 따른다.

| 단계 | 방법 | 잡히는 것 |
|---|---|---|
| 1 | `python3 -m json.tool <파일>` | 문법 오류만 |
| 2 | 레이블 참조 정적 검사 | `target`·`scene id`·`character` 오타 — **1로는 안 잡힌다** |
| 3 | godot-mcp: `godot_editor_edit` stop → run | 실제 진행 |
| 4 | `godot_runtime_state`로 `current_label`·`distance` 확인 | 분기가 의도대로 갔는지 |

3~4는 **Godot 에디터가 열려 있어야** 가능하다.

### 허브 특유의 검증 항목

| 확인할 것 | 방법 |
|---|---|
| 반복이 성립하는가 | 이벤트 완료 후 `current_label`이 `AprilHub`로 돌아오는가 |
| 카운터가 오르는가 | 반복마다 `april_events` 증가 확인 |
| 중복 방지가 되는가 | 완료한 이벤트의 버튼이 사라지는가 (6절 적용 후) |
| 게임오버가 작동하는가 | `distance`를 강제로 80 이상 설정 후 이벤트 종료 |
| 진행 분기가 작동하는가 | `april_events`를 강제로 4 설정 후 이벤트 종료 |

마지막 두 항목은 `set_var`를 넣은 임시 테스트 레이블을 만들어 확인하는 것이 빠르다. 기존 `Test_Cond_*` 노드가 같은 방식의 선례다.
