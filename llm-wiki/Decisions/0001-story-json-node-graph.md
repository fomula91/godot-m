# 0001 — 스토리 데이터를 JSON 노드 그래프로 구동

## 상태
채택 (구현됨)

## 맥락
분기형 비주얼 노벨의 시나리오(대사·선택지·조건 분기·연출 명령)를 코드와 분리해 관리해야 한다. 시나리오 원본은 `docs/script_full.md` 등 마크다운 문서로 작성되어 있고, 이를 게임이 읽을 수 있는 형태로 변환해야 한다.

## 결정
스토리를 `story/<월>/<장>.json`의 노드 그래프로 표현한다. 각 노드는 키로 식별되고 대사·선택지(`key`/`target`)·조건·연출 명령을 담는다. 파싱과 진행은 autoload 싱글턴 `StoryManager`(scripts/autoload/story_manager.gd)가 전담한다.

## 근거
- 텍스트 포맷이라 diff·리뷰가 가능하고, 시나리오 작가가 GDScript를 몰라도 편집 가능.
- 노드 키 기반 점프라 허브 구조(4월 이벤트)·엔딩 분기를 자연스럽게 표현.
- 대안이었던 GDScript 하드코딩은 분기 규모(19개 장 예정)에서 유지보수 불가, Dialogic 등 외부 애드온은 Supabase 통계·거리감 시스템 같은 커스텀 요구에 맞추기 어려워 기각.

## 결과·트레이드오프
- 얻는 것: 시나리오/코드 분리, 장 단위 파일 분할.
- 감수하는 것: 노드 키·target 오타가 컴파일 타임에 안 잡힘 — JSON 파싱 통과 ≠ 정상 동작. 게임 실행으로 해당 노드까지 진행해야 검증됨 (CLAUDE.md 검증 표 참조).

## 재검토 트리거
노드 수가 수백 단위로 늘어 오타 사고가 반복되면 스키마 검증 도구(story-validator) 또는 에디터 툴링 도입을 검토한다.
