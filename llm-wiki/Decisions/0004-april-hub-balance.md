# 0004. 4월 허브의 구조와 밸런스를 확정한다

## 맥락

4월 파트는 `AprilHub`를 중심으로 이벤트를 반복 선택하는 허브 구조로 기획되었으나, 아직 구현되지 않았다.
새 원고(`docs/01.new_story.md`)를 JSON으로 변환하기에 앞서 구조를 점검한 결과, **서로 연쇄된 허점 3종**이 드러났다.

```
H-1 이벤트 중복 선택 가능 → 고치면 H-2가 드러남
H-2 게임오버 도달 불가    → 고치면 H-3이 드러남
H-3 4월 선택이 결말에 무영향
```

특히 H-2는 수치로 확인되었다. 거리감을 **올리는** 선택지가 게임 전체에 3개(+15, +5, +5 = 총 +25)뿐이고 나머지 이벤트는 어느 선택지를 골라도 거리감이 줄어들어, **의도적으로 최악만 골라도 70**에 그친다(게임 오버는 80). 현재 게임 오버에 도달하는 유일한 경로가 H-1(같은 이벤트 반복)이므로, 실패 조건이 사실상 버그에 의존하고 있었다.

또한 새 원고의 프롤로그~3화가 허브 이벤트 성립 조건을 만족하지 못한다는 점도 확인되었다(기존 미결 C-5·C-6).

## 결정

7건을 함께 확정한다. 개별로는 성립하지 않고 서로를 전제하기 때문이다.

| # | 결정 |
|---|------|
| **C-5·C-6** | 자리배정·수학시간을 **선형 도입부로 이관.** 허브는 원고 4화부터 시작하고 허브 이벤트는 4종(조별수업·점심시간·수학여행·보지않았다) |
| **H-1** | `choice` 항목에 `condition` 필드를 추가해 **관람한 이벤트를 숨긴다.** `choice_controller.gd`에 3줄 |
| **H-2** | **시간 경과 페널티 +10** (허브 복귀마다). "보지 않았다" −15 → **−5** |
| **H-3** | 엔딩 A에 **`distance <= 45`** 조건 추가 |
| **H-5** | 허브 진입 시 거리감 구간별 내레이션 (수치는 노출하지 않음) |
| **H-6** | 진행 조건 **`april_events >= 4` → `>= 3`** |
| **H-4** | 2차 선택지에 **화제 플래그**(`topic_*`) 부여 — 원고 4~6화 집필과 동시 적용 |

### 허브 이벤트 판정 기준

향후 원고를 배치할 때 쓸 기준을 함께 정한다. **셋을 모두 만족해야** 허브 이벤트가 될 수 있다.

1. 순서에 의존하지 않는다
2. 세계 상태를 비가역적으로 바꾸지 않는다
3. 그 자체로 완결된다

원고 프롤로그~3화는 전부 이를 위반한다. 1화는 "처음 말을 건다"가 한 번뿐이고, 2화는 자리를 두 번 바꿀 수 없으며, 3화는 "옆자리"(2화의 결과)를 전제한다.

### 확정 밸런스

| 항목 | 값 |
|------|-----|
| 초기 거리감 | 50 |
| 게임 오버 | `distance >= 80` |
| 진행 조건 | `april_events >= 3 AND distance < 80` |
| 시간 경과 페널티 | 허브 복귀마다 +10 |
| 엔딩 A 조건 | `distance <= 45` |

3회 플레이 검산: **최선 45**(엔딩 A) / 보통 55(엔딩 B) / **최악 85**(게임 오버).

## 근거

**왜 페널티가 +5가 아니라 +10인가.** 처음에는 +5로 검토했으나, C-5·C-6 확정으로 **유일한 +15 선택지("친구와 대화한다")가 허브에서 빠져나갔다.** 남은 양수 선택지는 +5 두 개뿐이라 +5 페널티로는 최악 플레이가 70에 그쳐 게임 오버가 여전히 불가능했다. +10이어야 85에 도달한다.

**왜 엔딩 A 조건이 30이 아니라 45인가.** 페널티 +10 확정으로 최선 플레이의 도달치가 정확히 45가 되었다. 30으로 두면 엔딩 A가 수학적으로 도달 불가능해진다.

**왜 시간 경과 페널티인가.** 임계값 인하(80→65)는 싸지만 아슬아슬하고, 양수 선택지 증설은 원고 재작성을 요구한다. 페널티는 수치 한 줄이면서 **서사와도 맞는다** — 수아는 먼저 다가오지 않는 캐릭터이고 프롤로그가 통째로 그것을 보여준다. 플레이어의 과제가 "관계를 쌓는 것"에서 **"흘러가는 시간을 거스르는 것"** 으로 바뀐다.

**왜 엔딩에 거리감을 참여시키는가.** 밸런스 장치가 아니라 주제의 구현이다. 같은 말이라도 쌓아온 시간에 따라 다르게 닿는다 — 이 작품이 하려는 이야기 그 자체이며, 4월의 모든 선택에 소급해서 의미가 생긴다.

## 결과

**좋아지는 것**

- 실패 조건이 실제로 작동한다. 악수를 2회 이상 두면 게임 오버에 도달한다.
- 4월 플레이가 엔딩에 직결된다. 엔딩 A가 완벽한 4월을 보낸 플레이어에게만 열리는 진엔딩이 된다.
- 같은 장면을 반복해서 보는 일이 없어진다.
- `choice`의 `condition` 확장은 균열 파트와 엔딩 분기에서도 재사용된다.

**나빠지는 것 / 감수하는 것**

- **엔딩 A의 마진이 0이다.** 최선 플레이가 정확히 45라 한 번의 차선 선택도 허용되지 않는다. 의도된 것이지만 빡빡하다.
- 허브 이벤트가 4종으로 줄어 자유도가 낮다. 3회를 채우면 **반드시 하나는 보지 못한다.** 원고 4~6화 집필 시 이벤트를 보강해야 한다.
- H-4(화제 플래그)나 이벤트 신설이 들어오면 **밸런스 재산출이 필요하다.**
- 코드 수정이 하나 발생한다(`choice_controller.gd`). JSON만으로는 H-1을 해결할 수 없다.

**새로 생긴 미결**

- 도입부로 옮긴 자리배정·수학시간의 선택지를 유지할지 미정(O-8). 기본값은 "도입부는 거리감 변동 없음"이며, 변동시키면 검산표를 다시 계산해야 한다.
